# LogPulse Quick Project Guide

This is a short orientation guide for understanding what each major part of LogPulse does.

## 1) Big Picture

LogPulse has two apps:

- Backend (FastAPI + workers) in backend
- Frontend (React dashboard) in frontend

Main data flow:

1. Synthetic logs are generated by backend stream tools.
2. Logs are persisted and optionally published to Kafka topic logs.raw.
3. Stream consumer reads Kafka and persists enriched events.
4. Anomaly detection (rules + model score) tags suspicious events.
5. API and WebSocket endpoints expose logs, anomalies, metrics, batch stats, and RCA reports.
6. Frontend pages render live status, timelines, metrics, batch summaries, and agent RCA output.

## 2) Backend: What Does What

- backend/app/main.py
  - FastAPI app entrypoint.
  - Initializes DB and starts/stops RCA worker during app lifespan.
  - Registers REST routes under /api/v1 and websocket routes under /ws.

- backend/app/runner.py
  - CLI process launcher for backend modes:
    - api
    - stream
    - batch
    - agent

- backend/app/api/router.py
  - Combines health, logs, and agent route groups.

- backend/app/api/v1/logs.py
  - REST endpoints for:
    - log generation/search/recent logs
    - anomaly list and anomaly detail
    - stream status and live metrics
    - stream consume trigger
    - batch status/run/history metrics

- backend/app/api/v1/agent.py
  - RCA endpoints:
    - queue RCA analysis
    - list reports
    - fetch report by id

- backend/app/ws/routes.py
  - WebSocket channels:
    - /ws/logs
    - /ws/anomalies
    - /ws/metrics
  - Supports last_sequence resume for logs and anomalies.

- backend/app/stream/pipeline.py
  - Core stream logic:
    - event enrichment and anomaly scoring
    - in-memory recent/event buffers
    - register and sequence live events
    - search, anomaly detail, live metrics, pipeline status

- backend/app/stream/consumer.py
  - Kafka consumer side of stream pipeline and persistence path.

- backend/app/batch/scheduler.py
  - Batch run orchestration:
    - run once
    - run loop
    - track latest status
    - load batch history

- backend/app/agent/orchestrator.py
  - RCA orchestration using LLM tools.
  - Builds analysis result from anomaly context + tool evidence.

- backend/app/agent/worker.py
  - Background RCA report queue worker.
  - Picks queued reports, runs analysis, persists completion/failure.

- backend/app/storage
  - DB setup and SQLAlchemy models (raw events, batch runs, RCA reports).

## 3) Frontend: What Does What

- frontend/src/App.tsx
  - Main route map and app-level error boundary.

- frontend/src/pages
  - live-logs-page.tsx
    - log generation controls, consume trigger, live status, combined log table
  - anomaly-timeline-page.tsx
    - live anomaly feed + anomaly detail modal
  - metrics-page.tsx
    - live service-level metrics breakdown
  - batch-analytics-page.tsx
    - batch status, run trigger, run history, service aggregates
  - agent-console-page.tsx
    - RCA trigger, report list, selected report details

- frontend/src/api
  - client.ts
    - shared API request helper and typed error handling
  - logs.ts
    - typed REST client functions for all backend endpoints used by UI

- frontend/src/hooks
  - React Query data hooks and mutation hooks.
  - WebSocket hooks for logs/anomalies/metrics with reconnect + resume behavior.

- frontend/src/components
  - layout/app-shell.tsx for top navigation frame
  - page components and shared UI primitives in components/ui

- frontend/src/lib
  - helpers for error messages, stable event keys, and safe time formatting.

## 4) Most Important Runtime Flows

### A) Live Log Monitoring

1. UI triggers logs/generate.
2. Backend creates and enriches events.
3. Events go to DB, optional Kafka publish, and in-memory stream buffer.
4. UI receives updates through /ws/logs and /ws/metrics.

### B) Anomaly Investigation

1. Anomalies are tagged in stream pipeline.
2. UI sees them on /ws/anomalies plus API history fallback.
3. Clicking anomaly opens context via anomalies/{event_id}.

### C) RCA Agent

1. UI queues report with agent/analyze.
2. Worker processes queued report asynchronously.
3. UI polls reports and displays final RCA summary, cause, evidence, timeline.

### D) Batch Analytics

1. Batch run executes service aggregate job.
2. Result saved in batch_runs.
3. UI loads latest and historical summaries from metrics/batch.

## 5) Which Process To Run For What

- API server only:
  - cd backend
  - uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload

- Stream consumer loop:
  - cd backend
  - uv run python -m app.runner --mode stream

- One batch run:
  - cd backend
  - uv run python -m app.runner --mode batch

- Batch loop:
  - cd backend
  - uv run python -m app.runner --mode batch --batch-loop

- Frontend:
  - cd frontend
  - bun install
  - bun run dev --host 0.0.0.0 --port 5173

## 6) Quick Troubleshooting Checklist

- UI has no data:
  - Check /api/v1/health and /api/v1/stream/status.
  - Confirm backend API is running on port 8000.

- Kafka flow not moving:
  - Check Kafka services and stream consumer process.
  - Trigger stream consume from UI or /stream/consume endpoint.

- RCA stuck in queued:
  - Confirm agent worker is enabled and running.
  - Confirm model credentials are configured if live LLM analysis is required.

- WebSocket drops:
  - UI now reconnects and resumes from last sequence; confirm backend websocket routes are reachable.
